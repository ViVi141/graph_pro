## 2. 拟合公式

### 2.1 仅巡逻（cycle2）：线性于单位数

- **exe_fn ≈ 2.685 · U + -28.64**　(R²=0.9755, RMSE=26.8, n=6)
- **exe% ≈ 0.01011 · U + -0.0917**　(R²=0.9632, RMSE=0.1248)

其中 **U = groups × 4**（每组 4 人）。

### 2.2 仅站岗（none）：线性于单位数

- **exe_fn ≈ 1.020 · U + -19.68**　(R²=0.9822, RMSE=8.2)
- **exe% ≈ 0.00385 · U + -0.0580**　(R²=0.9975)

### 2.3 双因子（全体点）

令 `M=1` 表示移动（move1/cycle*），`M=0` 表示站岗：

**exe_fn ≈ -28.29 + 1.085·U + 1.552·(U·M)**　(R²=0.9770, RMSE=21.1)

**exe% ≈ -0.0934 + 0.00412·U + 0.00578·(U·M)**　(R²=0.9661)

### 2.4 固定 24 组时，路点「个数」几乎无关

| wp_mode | wp 总数 | exe_fn | exe% |
|---|---:|---:|---:|
| `none` | 0 | 64 | 0.2957 |
| `move1` | 24 | 207 | 0.7527 |
| `cycle2` | 48 | 202 | 0.7517 |
| `cycle4` | 120 | 210 | 0.8031 |

仅移动点对 `wp_total` 线性拟合：斜率 **0.0497 exe_fn / 路点**（R²=0.377）→ **路点条数不是主因**；**是否在移动**才是主因（none→move 跃迁远大于 move1→cycle4）。

## 4. 结论（任务设计）

1. **exe 开销 ≈ 线性于 AI 人数**（移动与站岗各自一条直线，R² 高）。
2. **路点数量（1/2/5）在已移动前提下几乎无增量**；从 `none` 打开移动才出现阶跃。
3. 性能预算优先：**少单位** 与 **能站岗就禁 PATH**；不要指望靠「少写几个 waypoint」省 CPU。
4. 复跑：`powershell -File server\sweep-ai-wp.ps1 -Groups 24 -WpMode cycle2`
5. 跨 CPU 流畅度估算（需本机标定）：[18-mission-cpu-estimate.md](18-mission-cpu-estimate.md)
