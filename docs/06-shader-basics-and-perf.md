# 着色器是什么，以及能不能靠它做性能优化

日期：2026-10-22

## 1. 一句话

**着色器 = 跑在 GPU 上的小程序**。显卡每画一个顶点、每填一个像素，就执行一次对应的着色器。

- **顶点着色器（VS）**：把模型顶点从模型空间变换到屏幕空间（每个顶点一次）
- **像素着色器（PS）**：算出这个像素最终是什么颜色（每个像素一次，**最贵**）
- **几何着色器（GS）**：A3 用它做云（`GSSimulWeatherClouds`）
- **计算着色器（CS）**：通用 GPU 计算，A3 里基本没用（`Shaders_5_0_CS.shdc` 只有 9 KB）

一次 1080p 全屏 pass = **约 207 万个像素**，每个像素都跑一遍 PS。所以"全屏后处理"贵不贵，取决于它有几个 pass、每个 pass 采样几次贴图。

## 2. A3 里的着色器分三类

| 类别 | 作用 | 数量（我们导出的） |
|---|---|---|
| **材质着色器** | 物体表面如何被光照亮：法线、镜面、菲涅尔、贴图混合 | PS 830 + VS 3301（5.0 缓存） |
| **后处理着色器** | 场景画完之后的成像：tonemap、AO、bloom、AA、调色 | PP 144（5.0）/ 43（4.0） |
| **地形/水面/天空** | 专用着色器，视距和反射主要成本在这 | 混在 PS 里 |

一台机器启动游戏后，实际创建的像素着色器大约 **240 个**（我们日志实测），其余是按需加载的变体。

## 3. 改着色器能改什么

| 想改 | 改哪 | 性质 |
|---|---|---|
| 画面"像不像照片" | tonemap / AO / bloom / AA | 真提升（改引擎算法） |
| 物体"塑料感" | 材质 PS 的 specular / fresnel / 法线采样 | 真提升（改光照响应） |
| 帧率 | 减少采样次数、降精度、砍 pass、降分辨率 | 真优化 |

## 4. 性能优化：能，但只在 GPU 瓶颈时有效

这是关键前提。**A3 大部分场景是 CPU 瓶颈**（AI、绘制调用、模拟），此时改着色器几乎不掉帧也不涨帧。

判断方法（1 分钟）：

1. 同一场景，1920×1080 记一次 FPS
2. 改成 960×540 再记一次
3. **FPS 接近 → CPU 瓶颈**（改着色器没用）；**FPS 接近翻倍 → GPU 瓶颈**（改着色器有用）

更准的：用 PresentMon 看 GPU busy time / 帧时间分布。

## 5. 在你机器上值得试的着色器级优化（按收益排序）

| 目标 | 做法 | 预期收益 | 画质代价 |
|---|---|---|---|
| **SSAO** | 采样数减半 + 半分辨率 + 模糊代替大核 | 大（iGPU 上最贵之一） | 中（接触阴影变糊） |
| **SMAA → FXAA** | 直接替换成 1 pass 的 FXAA | 中 | 小（边缘变软） |
| **Bloom** | mip 层数减少、阈值提高 | 中 | 小（光晕变小） |
| **阴影** | 减少 PCF 采样数、降低 shadow map 分辨率 | 中 | 中（阴影锯齿） |
| **水面 SSR** | 关掉或降分辨率 | 大（如果开着） | 大（水面变"死"） |
| **地形** | 减少细节贴图采样层数 | 中 | 中（远景变平） |
| **tonemap** | 合并多余的中间 pass | 小（一个全屏 pass ≈ 0.3 ms） | 无 |

前四项都可以用我们现在的注入器做 A/B：换一份 DXBC、跑同一段场景、看帧时间。

## 6. 风险与代价

- **视觉回归**：省掉的采样会变成噪点或糊
- **崩溃**：签名/常量缓冲对不上就黑屏（我们已经有前车之鉴）
- **维护**：A3 每次更新，运行时编译的着色器会变，指纹要重跑
- **不是万能**：CPU 瓶颈、内存带宽瓶颈、绘制调用过多，改着色器都救不了

## 7. 结论

- **画质**：改着色器是唯一"一次改、全局生效"的真提升手段（对比：逐物体改 rvmat 是 O(N)）
- **性能**：可行，但必须先确认 GPU 瓶颈；最值得做的是 SSAO 和 AA 这两个"每像素都跑、算法又笨重"的 pass
- **顺序**：先做画质（tonemap/AO），再做性能（同一条注入管线复用）
