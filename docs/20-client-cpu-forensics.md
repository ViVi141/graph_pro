## 0. 结论摘要

| 线 | 结论 |
|---|---|
| **客户端（YAAB）** | CPU 大头是**渲染命令处理**，不是 AI/脚本：主线程 ~33% 采样在 `0x169B288`（每帧一次、约 8.5 ms）；渲染线程 ~25% 在 `0x1698F85`（CmdExecute）；核显驱动只占活跃样本 ~2% |
| **DS** | 交战墙是**主线程串行**：641 单位混阵营 19 fps / 3.4 核（12 核里 9 个闲置）；同人数不交战 28.9 fps / 1.6 核；897 单位 8.4 fps |
| **降频实验** | 成对 50% 降频 641 单位 **+16% fps**，但**开火 −31%** → 收益主要来自 AI 少打，**否决为优化补丁** |
| **可注入空间** | 客户端命令处理循环是引擎内部约定（184 字节/条、虚调用、屏障），外部改不了；唯一杠杆是**减命令条数（draw call）** |

| 组 | 单位 | fps | 帧长 | 总 CPU | 主线程 | 主线程占用/帧 |
|---:|---:|---:|---:|---:|---:|---:|
| 0 | 1 | ~28（封顶） | — | 0.4% | 0.9% | — |
| 96 | 385 | 28.4 | 35 ms | 233% | 53% | 18.6 ms |
| 128 | 513 | 29.3 | 34 ms | 307% | 69% | 23.4 ms |
| 160 | 641 | **18.3** | 55 ms | 337% | 76% | 41.7 ms |
| 192 | 769 | **10.0** | 100 ms | 232% | 80% | 79.7 ms |
| 224 | 897 | **8.4** | 119 ms | 258% | 81% | 96.3 ms |

**对照**：641 单位全 west（不交战）→ **28.9 fps、~1.6 核**；混阵营 → 18.3 fps、3.4 核。

结论：
- 28–29 fps 是节流上限（0 AI 时也是 28），不是 CPU 上限；
- 帧率由**主线程串行耗时**决定；12 核最多用 3.4 核；
- 同一人数，只改阵营 → fps 18.3 ↔ 28.9，**交战是触发条件**。

### 4.3 gpmeasure（命令处理函数）

    calls = 6,352        calls_per_s = 31

- ≈ 每帧 1 次（当时约 30 fps），**不是每条 draw 一次**
- 主线程 ~800 ms/s × 33% ÷ 31/s ≈ **8.5 ms/帧** 花在该函数

反汇编（`0x169B288`，462 B）显示它是**命令数组处理循环**：

    mov eax,[rbx+0xB8000C] / mov esi,[rbx+0xB80008]; sub esi,eax   ; 待处理条数
    imul rdi,rax,0xB8                                              ; 每条 184 字节
    cmp byte [rdi+0x14],0                                          ; 标记
    call qword [rax+0x18]                                          ; 释放缓冲
    add [rbx+0xB80028],eax / add [rbx+0xB8002C],eax                ; 累加统计
    lock or dword [rsp],0                                          ; 屏障
    inc dword [rbx+0xB8000C]                                       ; 游标
    pause
    call qword [rax]                                               ; 虚调用：整批交给下游

→ 逐条命令的 bookkeeping + 内存访问，**随命令条数线性**；无扩容/固定开销可修。

## 6. 失败的尝试与教训

### 6.1 目标获取降频（gpgate3）
- 641 单位：成对块 50% 跳过 → **+16% fps**
- 但 `Fired` 计数：**−31.3% 射击/分钟、−40.8% 射击/帧**
- 判定：收益 = AI 少打，**不是算法优化**，否决

### 6.2 采样偏差
- 挂起采样时 `GetThreadTimes` 不计挂起时间 → 被采样线程的 CPU 被低估
- gpwatch 的 `cpu` 列曾每 5 s 重置 → 只代表最近窗口；v5 改为累计

### 6.3 失焦暂停
- Arma 单人默认失焦暂停；从 PowerShell 注入会暂停游戏
- 对策：`start_delay_s`（注入后切回游戏再开始采）

### 6.4 YAAB 场景差异
- 各场景负载差异大，60 s 窗口可能只覆盖轻场景
- 对策：180 s + 30 s 快照，按窗口挑重场景

### 6.5 其他
- `E8` 扫描会命中指令中段（假调用点）→ 必须从函数起点反汇编校验
- `funcs.bin` 必须与目标二进制匹配（客户端/服务器 RVA 不同）

## 7. 边界

| 想做 | 可行性 |
|---|---|
| 减 draw call / 视距 / 物体数 | 有效，但属内容/配置层 |
| 改命令处理循环（184 B/条、虚调用） | 违反引擎内部约定，必然崩 |
| 改作业系统线程数 | 可改（`0x3866B8` / `0x306F18` 的 `B9 04`），但实测 DS 未饱和 |
| 目标获取降频 | +16% fps 但 AI 变钝 31%，否决 |
| 单叶子替换 | 平坦 profile（docs/13/16），否决 |

## 8. 复现

1. DS：`saturate2.ps1 -GroupList 96,128,160,192,224`（需 160 组任务模板）
2. 客户端采样：部署 `gpwatch.dll` + `funcs.bin`(客户端) + `injector.exe` + `GP_watch.cfg`，YAAB 中注入，等待快照
3. 客户端计数：`gpmeasure.dll` + `GP_measure.cfg`（`rva=169B288`），注入后读 `GP_submit.txt`
4. 安全：仅单人/编辑器；采样期会明显卡顿；用完重启游戏
